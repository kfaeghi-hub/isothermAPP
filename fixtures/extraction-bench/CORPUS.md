# Extraction benchmark — corpus manifest

**This file is committed. Almost none of the corpus is.** The schedules described
below are client documents living in gitignored `samples/`; the one committed
member is the synthetic hostile fixture, so a fresh clone can always measure
something rather than reporting a pass on an empty run.

Run it:

```
node --env-file=.env extraction-bench.mjs             # scored + surveyed
node --env-file=.env extraction-bench.mjs --survey    # the per-file table
node --env-file=.env extraction-bench.mjs --json      # machine output
```

---

## The metric (ruled 2026-08-11)

A file is **CLEAN** when all four hold:

1. **Every unit extracted** — no shortfall, and no phantom that is not on the sheet
2. **Every unit correctly typed**
3. **≥ 95% of its spec values correct**
4. **Every genuine ambiguity flagged**, never guessed

**Corpus pass rate** = clean ÷ **scored** files. Target **≥ 90%**.

## Scored versus surveyed — and why both numbers always print

A file is **scored** only against expectations **written by hand from the sheet**.
Truth recorded by running the parser and keeping whatever came out asserts that
the code still does whatever it does, and passes just as happily when the
behaviour is wrong. This repo has paid for that lesson twice.

Every other file is still **run**, and its structural signals reported, but it is
counted as **surveyed, not scored**. A pass rate over 4 files must never be read
as a pass rate over 37, so the report prints both numbers every time.

Converting a surveyed file to a scored one is a deliberate act: read the sheet,
write the truth, add it to `EXPECT` in `extraction-bench.mjs`. **The corpus is the
curriculum — every failing file becomes a named fixture with its failure class,
and nothing beats the system twice.**

### The hostile fixture — `hostile-schedule.xlsx`

Generated by the committed `gen-hostile-schedule.mjs`, so it is reproducible and
carries no client content. It stacks six real failure modes into one sheet:

1. **A merged banner sharing its row with a group header** (`PUMP SCHEDULE …` at
   A1, `ELECTRICAL DATA` at H1) — the exact shape that made `findTitle` discard
   "PUMPS" on Avondale and let SERVICE type two pumps as boilers.
2. **A two-tier header** — `PERFORMANCE` / `MOTOR` group headers over the real
   column names, so the header row is row 3 and row 2 is spans.
3. **Alien column names** — `EQPT NO.`, `DUTY`, `SERVES`, `Q [USGPM]`,
   `TDH [FT WG]`, `PIPE SZ [IN]`, `PWR [BHP]`, `SPD [RPM]`. Not one appears in
   any deterministic synonym list.
4. **A genuine ambiguity with no answer on the page** — a bare `MBH` column on a
   unit that could carry either an input or an output rating, and the sheet never
   says which. The right behaviour is to extract it and **ask**.
5. **A duty that names the equipment it serves** — `BOILER B-1 PRIMARY`.
6. **A prose tail** — a NOTES row that is not a unit.

## Baseline — 2026-08-11, deterministic path only

**3 / 4 scored files clean (75%).** Target ≥ 90%.

| File | Verdict | Note |
|---|---|---|
| `AS.xlsx` | CLEAN | 1 unit, spec 100% |
| `Boilers.xlsx` | CLEAN | 2 units, spec 100% |
| `PMPs.xlsx` | CLEAN | 4 units, spec 100% |
| `hostile-schedule.xlsx` | **FAIL** | `ambiguity-unflagged` |

The hostile fixture fails on exactly one clause, and it is the honest one: the
deterministic path **has no mechanism to flag an ambiguity at all**. Requirement 4
is real and unmet, and naming it is what makes the next build measurable rather
than felt. Everything else on that sheet it gets right — the banner title is
recovered past the group header, all four units are typed `pump` despite a duty
that says `BOILER`, the NOTES row is refused, and every spec value is captured.

### What the hostile fixture found on its first run

`MBH` sits in column **J**, outside the `MOTOR` merge (`G2:I2`), and was labelled
**`MOTOR MBH`**. Forward-fill carries a group header across every following blank
cell, and `read-excel-file` returns a merged cell as *value plus nulls* without
ever reporting the merge's width — so the fold cannot know where `MOTOR` ends.
A rules-only reader cannot fix this; the merge extent is not in the data it is
given. Recorded here as a named defect rather than patched around.

## Phase 2 — the model leg, 2026-08-12

`--with-ai` runs the shipped model read (`api/_shared/sheet-model-read.ts`) over
the corpus. **37 files, $3.92, 10.6c per sheet.**

| | rules | model |
|---|---|---|
| scored corpus clean | 3/4 (75%) | **4/4 (100%)** |
| typed, on files the model read | 209/298 (70%) | **203/205 (99%)** |
| VAV-lvl1 / VAV-lvl2 | 0/29, 0/22 | **29/29, 21/21** |
| questions raised | none possible | **27** |

**The denominators differ and that is the point.** Five files produced no model
rows at all — `AHU-Coils1`, `DOAS-1`, `DOAS-3`, `DOAS-coil1` (contract-output) and
`FanCoils` (truncated) — so 205 is not 298. *On the sheets it read, the model
typed nearly everything the rules could not; on five sheets it read nothing.*

**The five are now the curriculum.** Four failed the output contract and one ran
out of budget on a 64-row sheet, which are two different problems: one is shape,
one is size. Neither is fixed by trying again.

## Phase 4b — the read-leg repair, 2026-08-12

**Zero zero-read files. 37/37 usable, up from 32/37.**

| leg | typed / 298 | | |
|---|---|---|---|
| rules | 209 | 70% | `[MEASUREMENT — deterministic]` |
| model | **267** | **90%** | `[SAMPLE — one run]` |
| merged | **269** | **90%** | `[SAMPLE — contains the model leg]` |

**Cost 533.5c — 14.4c per sheet READ and 14.4c per USABLE sheet.** The two numbers
**converged**, which is what they were built to show: nothing is being paid for
twice any more. Chunking: 6 sheets in 33 bands (x5.5), 64 calls over 37 sheets,
**no tag appeared in two bands**.

### Model-leg variance, four runs

| run | typed / 298 | note |
|---|---|---|
| 1 | 203 | 68% |
| 2 | 185 | 62% — failing set changed |
| 3 | 155 | 52% — both FanCoils truncated |
| *(void)* | *53* | *not a measurement: 14 files hit an unretried rate limit* |
| **4** | **267** | **90% — after the fragment rule, chunking and transport retry** |

The rules leg returned **209 to the row on all four**. The variance was dominated
by read FAILURES, not read quality — which is what Phase 4b was authorised to
prove, and it proved it.

### One caveat on the denominator

Merged returned **300 rows against a 298 denominator**: the model found two units
the rules leg never saw. **298 is the RULES leg's count**, made permanent as the
divisor — it is not the sheet's ground truth, and where the model finds more, the
merge exceeds it. Worth knowing before 298 is read as "every unit in the corpus".

## Standing rules

- **Skip loudly.** A corpus directory that is absent prints by name and says it is
  skipping, not passing. A green run on a corpus that was not there is the silence
  class in its purest form.
- **A file that cannot be read is a failure class**, not an absence. Unreadable
  files are counted and named separately.
- **The bench reports; it does not gate.** A regression shows as a falling rate and
  a named failure class, which is more useful than a red suite that says only "no".
- **The number prints in RELEASES when it moves.**
